What:		/sys/bus/usb/devices/<interface>/mct/
Date:		October 2026
KernelVersion:	7.2
Contact:	Filip Piękoś <mail@filippiekos.com>
Description:
		Per-device information and settings of the mct driver (MCT
		Trigger USB displays). One value per file.

		Read-only, all devices:

		chip		"t2" or "t6"
		model		USB product string
		driver_version	DRM driver name and version, e.g.
				"mct_t6 0.26.0"
		connector	DRM connector name, e.g. "card2-HDMI-A-3"
		mode		current mode "WxH@Hz", or "off"
		modes		the modes the connector offers, one per line:
				"WxH@Hz" (two decimals), the pixel clock in
				kHz, and "preferred" for the preferred mode
		updates		frames sent since probe
		bytes		bytes sent since probe
		errors		transfer errors since probe

		Read-only, Trigger 6:

		pixel_format	"NV12", "YUV444", "RGB24", "RGB32" or "-"
		feature_level	the device's feature level, -1 if unknown
		vram_mb		video memory in MiB
		usb_speed	"usb2" or "usb3"
		platform	"lite" or "super-lite"
		board		the board name the chip reports ("project
				code", e.g. "JUA254H"), or "-"
		firmware	boot code and image code versions, two
				8-digit hex numbers, e.g. "16062899 17091401"
		serial		the chip's serial number as 16 hex digits,
				or "-" if it has none
		display_flags	display function flags from the device's
				DISP descriptor, hex
		functions	the device's functions, one per line: id
				(4 hex digits) and name, e.g.
				"5621 Trigger 6 External Graphics"
		device_modes	the device's own mode table, one mode per
				line: "WxH@Hz" and the pixel clock in kHz
		clock_limits	the driver's pixel clock limits in kHz: for
				all modes, and for modes 2560 pixels wide or
				more
		recoveries	device restarts after transfer errors

		Read-only, Trigger II:

		pixel_format	"RGB24" (sent as planar RLE), or "-" while off

		backlight	name of the backlight device in
				/sys/class/backlight/, or "-"

		Read-write:

		format		(Trigger 6) "auto", "rgb24", "rgb32", "yuv444",
				"nv12". auto: exact RGB or YUV 4:4:4 while the
				screen is still, NV12 during large changes.
		all_modes	(Trigger 6) 0 or 1: also offer modes larger than
				the monitor's native resolution. A change sends
				a hotplug event so userspace probes again.
		lossy		(Trigger II) 0 to 8: maximum lossy tolerance for
				updates too big for one frame (for green; red
				gets 1.5 times, blue 2 times); 0 = lossless.
		motion		(Trigger II) "lossy" or "half": with "half",
				full-screen updates too big for one frame
				are sent at half resolution and upscaled 2x
				by the chip, refined once motion stops.

		The module parameters of the same names are the values new
		devices start with.
